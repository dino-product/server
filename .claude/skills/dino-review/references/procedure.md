# AI 리뷰

리뷰 요청만으로 코드 수정·댓글 게시를 하지 않습니다. 예외는 저장소가 워크플로로 위임한 [자동 리뷰](automation.md#automation)이며, 그 범위 밖의 게시는 하지 않습니다. [자동 검사와 리뷰의 역할](../../dino-testing/references/verification.md#evidence)에 따라 유효한 결과를 재사용하고 미검증 요구사항·영향·검사 자체의 적절성을 검토합니다.

1. **범위:** 목적·완료 조건·실제 base/head SHA와 커밋 순서를 확인합니다. 선행 PR 변경과 현재 diff를 구분하고 같은 SHA의 통계·검사 근거를 재사용합니다. 기준이 바뀌면 영향을 받는 범위를 다시 확인합니다.
2. **검토:** 커밋 순서대로 구현·호출부·테스트를 따라 요구사항·실패 경로·누락·한 변경 이유·중간 상태 완결성을 판단합니다. 최종 상태 검사와 커밋별 근거를 구분하며 미해결 조립 우려에는 해당 커밋 검사를 제안합니다. 발견은 위치·발생 조건·영향·근거를 갖추고 가설과 확정 결함을 구분합니다.
3. **연결:** 호출부·공개 계약·구현·설정·테스트의 일치를 확인합니다. 변경에 해당하는 [모듈 경계](../../dino-architecture/references/architecture.md#modules)·[소비자 변환](../../dino-architecture/references/architecture.md#external-models)·[내부 의존성](../../dino-architecture/references/architecture.md#layers)을 적용해 변경 전파를 확인하고 동일 원인 지적을 합칩니다.
4. **보고:** 중요한 결함부터 검토한 커밋·범위·검증 결과·미확인 사항을 알립니다. 일부 검토를 전체 완료로, 미실행 검사를 통과로 보고하지 않습니다. head가 바뀌면 새 diff와 영향을 받는 연결을 다시 확인합니다.

새 파일·삭제·이름 변경도 검토합니다. 생성물·잠금 파일·바이너리는 별도 표시하고 생성 원본·의존성 변경·파일 영향에 맞게 확인합니다. `numstat`에 줄 수가 없는 바이너리를 0줄로 보거나 큰 파일을 조용히 제외하지 않습니다.

중간 메모는 대화·임시 파일에 두고 PR에는 필요한 리뷰 순서·미분리 이유·중요 의존 관계만 남깁니다.
