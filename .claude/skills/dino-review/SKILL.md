# 팀 기준 리뷰

원본: [리뷰 절차](references/procedure.md), [자동 리뷰 운영·등급·형식](references/automation.md). CI의 자동 리뷰도 같은 문서를 따릅니다. 리뷰 요청만으로 코드를 고치거나 댓글을 게시하지 않습니다.

## 순서

1. **범위**: PR 종류, 노션 기능명세, base/head SHA, 커밋 순서를 확인합니다. 로컬 초안이 있으면 `.claude/pr-drafts/`를 읽습니다.
2. **다이어그램 대조 (가장 먼저)**:
   - 핵심 다이어그램의 참여자·호출 순서·실패 분기가 코드와 같은지 봅니다.
   - 구현 내용 표의 규칙마다 근거 테스트가 실제로 그 규칙을 검증하는지 봅니다.
   - 사람은 이것만 보고 판단하므로 불일치는 🔴입니다.
3. **코드 검토**: 커밋 순서대로 구현·호출부·테스트를 따라 결함(실패 경로·경계·동시성·상태 전이·누락)과 의미 판단이 필요한 컨벤션을 봅니다. 컨벤션은 `dino-architecture`의 references가 기준입니다. Spotless·Checkstyle·테스트·PR 규약 검사가 이미 판정한 것은 다시 지적하지 않습니다.
4. **단위**: 선언한 PR 종류가 diff와 맞는지, 종류가 섞였거나 다이어그램이 3개를 넘지 않는지 봅니다([PR 단위](../dino-pr/references/planning.md#unit)).
5. **보고**: [등급과 개수](references/automation.md#등급과-개수)와 출력 형식을 따릅니다. 확정 결함과 가설을 구분하고, 검토하지 못한 범위를 적습니다.
