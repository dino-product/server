# 도메인과 모듈 지도

현재 Application Module로 등록된 예제 모듈과 제품 골격의 책임·공개 계약·허용 의존성을 찾는 출발점입니다. 대상 모듈만 아래 문서·지침으로 이어서 읽습니다. 제품 골격의 설계와 향후 확장은 [바운디드 컨텍스트 지도](bounded-contexts.md#bounded-contexts), 제품 결정과 기능 흐름은 [기획 원본 색인](../planning/README.md#planning)이 가리키는 노션 정책서·기능명세가 원본입니다. 계획된 관계는 현재 허용 의존성과 구분합니다.

## 모듈별 책임과 공개 계약

| 모듈 | 소유 책임 | 공개 계약 | 허용 의존성 |
| --- | --- | --- | --- |
| `shared` | 오류 기반, OpenAPI 오류 문서화, 공통 응답 구현, 설정과 보안, JPA 감사 컬럼, 이벤트 발행 기록의 실패 재전송 | `shared::error` (`BaseCode`, `BusinessException`, `CommonErrorCode`), `shared::openapi` (`ApiErrorCodes`, `ApiErrorCodesGroup`), `shared::security` (`SecurityFilterChainCustomizer`, `ApiErrorResponseWriter`), `shared::persistence` (`BaseTimeEntity`) | 없음 |
| `user` | 사용자 등록과 사용자 요약 조회 | [User 공개 계약](user.md#공개-계약) | `shared::error`, `shared::openapi` |
| `auth` | 카카오·Apple OIDC 로그인, 계정(`Account`) 발급·조회·폐쇄(외부 식별 해제·이전 토큰 거부), 커밋 뒤 외부 연결 해제(카카오 연결 끊기·Apple 토큰 철회, 주기 재시도), Apple refresh token 암호화 보관, Access Token 발급·검증·로그아웃과 예제 subject 조회·등록 이벤트 후속 처리 | [Auth 공개 계약](auth.md#패키지와-공개-계약) — 인증된 계정 `AccountPrincipal`(소비자 `profile`·`organization`·`schedule`·`realtime`), 계정 폐쇄 `AccountClosure`(소비자 `profile`) | `shared::error`, `shared::openapi`, `shared::security`, `user` |
| `profile` | 계정의 가입 프로필(이름·연락처)·가입 상태·약관 동의 이력, [탈퇴](profile.md#profile-withdrawal)(개인정보 삭제·auth 계정 폐쇄 호출), 가입 미완료·필수 약관 재동의 전 계정의 API 이용 제한([가입 공통 검사](profile.md#profile-signup-gate)) | [Profile 공개 계약](profile.md#공개-계약) — 계정 표시 이름 조회 `ProfileLookup`. 요구 인터페이스 `WithdrawalBlocker` — 탈퇴 차단 판정(사유 `WithdrawalBlockReason`·건수 `WithdrawalBlock`), 구현 `schedule`, 구현 예정 `organization`(HM-319). 이벤트 `AccountWithdrawn` — 탈퇴 커밋 뒤 후속 처리, 구독 `schedule`·`notification`(앱 푸시 기기 삭제), 구독 예정 `organization`(HM-319) | `shared::error`, `shared::openapi`, `shared::persistence`, `auth` |
| `organization` | 발주사(회사 코드 포함)·직원 소속·기사 계약 — 현재 발주사 생성(최초 총관리자 소속·회사 코드 발급), 발주사 정보 조회·수정, 회사 코드 조회·변경, 총관리자 지정·해제, 회사 확인·참여 요청 생성·취소·내 신청 현황, 참여 요청 승인 대기 목록(신청자 이름은 profile `ProfileLookup`)·승인·거절(직원 소속·기사 계약 생성, 비활성 소속 재활성화), 계정·발주사의 활성 구성원 조회, 기사 계약 조회(계정의 계약 목록·발주사의 활성 계약 확인), 요청자의 내 소속 목록 조회, 직원·기사 유형 관리, 참여 인원 목록(이름은 profile `ProfileLookup`)·세부 유형 지정·비활성화·재활성화(기사 비활성화는 `TechnicianWorkRelease`로 대기함 반환), 작업 유형 관리(삭제 영향 건수·삭제 포함). 요청자 계정은 웹 어댑터가 auth의 `AccountPrincipal`로 받음. | `OrganizationMemberLookup` — 활성 직원 소속(`StaffMember`, 총관리자 표시 포함) 또는 활성 기사 계약(`TechnicianMember`) 조회, 소비자 `schedule`·`realtime`(연결 요청자가 직원인지 확인). `TechnicianContractLookup` — 계정이 모든 발주사와 맺은 기사 계약(`TechnicianContract`, 비활성 포함·활성 여부 표시)을 조회하고, 기사 계약이 그 발주사의 활성 계약인지 확인(`existsActive`). 둘 다 캐시 없이 DB 상태를 읽음. 소비자 `schedule`(배정할 기사 확인, 탈퇴 차단 판정·뒤처리). `OrganizationAccountLookup` — 직원 소속·기사 계약 식별자로 그 발주사의 활성 구성원 계정을 조회(다른 발주사·비활성·없음은 빈 값), 소비자 `notification`(알림 받을 계정). `WorkTypeLookup` — 작업 유형 선택 가능 확인(`isSelectable`, 참이면 유형 행 공유 잠금)과 삭제된 유형을 포함한 표시 정보(`WorkTypeLabel`) 조회. `MemberDirectory` — 직원 소속·기사 계약의 표시 정보(`StaffDirectoryEntry`·`TechnicianDirectoryEntry`, 계정 식별자·총관리자 여부·삭제되지 않은 유형 `MemberCategoryLabel`)와 활성 기사 계약 목록 조회. 두 계약의 소비자 `schedule`(임시 어댑터 교체 전이라 아직 호출 경로가 없음). 요구 인터페이스 `TechnicianWorkRelease` — 역할 변경·비활성화의 대기함 반환(역할 변경만 결과 `WorkReleased`·`WorkReleaseBlocked`, 기사 일정 잠금 대기 초과는 `TechnicianWorkReleaseBusyException`), 구현 `schedule`. 이벤트 `ParticipationRequestApproved`(희망·확정 유형)·`ParticipationRequestRejected`(거절 사유) — 승인·거절 커밋 후 소비, 소비자 `notification`(HM-277 예정). 요구 인터페이스 `WorkTypeRelease` — 작업 유형 삭제의 영향 건수(`WorkTypeDeletionImpact`)와 시작 전 작업의 유형 해제(`WorkTypeReleasedWork`), 구현 `schedule`. 이벤트 `WorkTypeDeleted` — 작업 유형 삭제와 유형 없음이 된 작업, 소비자 `notification` 예정 | `shared::error`, `shared::openapi`, `shared::persistence`, `auth`, `profile` |
| `schedule` | 작업 생애주기 — `domain`(Work 애그리게잇·값객체·배정 이력·완료보고·일정 겹침 정책)과 Application(작업 생애주기 유즈케이스 — 목록은 `application/port/in` 패키지, 출력 포트·오류 코드), Work 저장소·목록 조회 어댑터(JPA, PostgreSQL)와 기사 일정 잠금 어댑터(PostgreSQL advisory lock), 작업 변경·조회 HTTP API(`adapter/in/web`, 조회는 타임테이블·작업 목록·대기함 요약·작업내역 출력·작업 상세·진행 보드, 요청자는 auth의 `AccountPrincipal`), organization 요청자 조회·기사 계약 확인·계정의 기사 계약 조회 어댑터(ACL), organization 요구 인터페이스 `TechnicianWorkRelease`·`WorkTypeRelease` 구현(`adapter/in/organization`, 역할 변경·비활성화의 대기함 반환, 작업 유형 삭제의 영향 건수·시작 전 작업 유형 해제), profile 요구 인터페이스 `WithdrawalBlocker` 구현(`adapter/in/profile`, 탈퇴 차단)과 `AccountWithdrawn` 구독(`adapter/in/event`, 탈퇴 반환), 임시 출력 어댑터(빈 표시 정보(기사·등록자·작업유형)·가짜 사진 주소·모두 거부하는 작업 유형 확인, `local`·`test`·`dev`에서만 등록 — 운영(`prod`)과 프로필 없는 실행은 현재 기동하지 않음) | 작업 이벤트 `WorkAssigned`·`WorkReassigned`·`WorkRescheduled`·`WorkCancelled`·`WorkAccepted`·`WorkRejected`·`CompletionReportSubmitted`·`CompletionReportRequested`(발행 조건은 각 record Javadoc), 소비자 `notification`. 작업 저장 이벤트 `WorkChanged`(저장한 모든 변경, 식별자·시각만), 소비자 `realtime` | `shared::error`, `shared::openapi`, `shared::persistence`, `organization`, `auth`, `profile` |
| `notification` | schedule 작업 이벤트 기반 알림 — 알림 저장·알림센터(목록·안 읽은 수·읽음)·알림 설정 HTTP API, 기사 앱 푸시 발신 대기열(알림 저장 트랜잭션에 넣고 주기 작업이 수신 계정의 기기마다 FCM으로 횟수 제한 없이 재시도하며 보냄, FCM을 끈 `local`·`test`·`dev`는 기록만 하는 발신기), 앱 푸시 기기 등록·해제 HTTP API, profile `AccountWithdrawn` 구독(탈퇴한 계정의 기기 삭제). 받는 계정은 서비스가 organization 공개 계약 `OrganizationAccountLookup`으로 직접 조회 | 알림 이벤트 `NotificationCreated`·`NotificationRead`(받는 계정·시각만, 발행 조건은 각 record Javadoc), 소비자 `realtime` | `shared::error`, `shared::openapi`, `shared::persistence`, `schedule`, `organization`, `auth`, `profile` |
| `realtime` | 사무실 웹 실시간 갱신 — 발주사 직원의 SSE 연결 열기 HTTP API(`adapter/in/web`, 요청자는 auth의 `AccountPrincipal`, 직원 여부는 organization 공개 계약 `OrganizationMemberLookup`으로 직접 조회)와 인스턴스 메모리의 연결 목록(인스턴스·계정 상한, 유지 신호, 수명, 막힌 쓰기 정리, 종료 처리, `adapter/out/connection`). schedule `WorkChanged`·notification `NotificationCreated`·`NotificationRead`를 커밋 뒤 구독해(`adapter/in/event`) Redis Pub/Sub 채널로 모든 인스턴스에 알리고(`adapter/out/redis`), 받은 신호를 연결로 보냄(`adapter/in/redis`). 연결과 신호는 DB·Redis에 남기지 않음 | 없음 | `shared::error`, `shared::openapi`, `shared::security`, `organization`, `auth`, `schedule`, `notification` |

`realtime`은 공개 계약이 없고 연결 요청자가 발주사 직원인지 확인하기 위해 `organization`(`OrganizationMemberLookup`)을, 요청자 계정을 받기 위해 `auth`를, 연결이 끝날 때의 비동기 재디스패치를 인가에서 빼기 위해 `shared::security`를, 오류 코드·OpenAPI 오류 문서화를 위해 `shared::error`, `shared::openapi`를, 작업 저장·알림 변경 이벤트를 구독하기 위해 `schedule`·`notification`을 허용합니다. `notification`은 알림 저장·읽음 이벤트를 공개하고 schedule 작업 이벤트를 구독하기 위해 `schedule`을, 받는 계정을 찾기 위해 `organization`(`OrganizationAccountLookup`)을, 요청자 계정을 받기 위해 `auth`를, 탈퇴한 계정의 앱 푸시 기기를 지우려고 탈퇴 이벤트를 구독하기 위해 `profile`을, 오류 코드·OpenAPI 오류 문서화·Entity 공통 부모를 위해 `shared::error`, `shared::openapi`, `shared::persistence`를 허용합니다. `organization`은 schedule에 활성 구성원 조회·기사 계약 조회 계약을, notification에 구성원 계정 조회·작업 유형 조회·구성원 표시 정보 조회 계약 `OrganizationAccountLookup`을 공개하고, 오류 코드·OpenAPI 오류 문서화를 위해 `shared::error`, `shared::openapi`를, Entity 공통 부모를 위해 `shared::persistence`를, 요청자 계정을 받기 위해 `auth`를, 승인 대기 목록의 신청자 이름을 찾기 위해 `profile`을 허용합니다. 이 의존 때문에 profile은 organization 타입에 의존할 수 없고, profile이 organization의 판단이 필요하면 profile 루트의 요구 인터페이스로 뒤집습니다. `schedule`은 작업 이벤트를 공개하고 오류 코드·OpenAPI 오류 문서화를 위해 `shared::error`, `shared::openapi`를, Entity 공통 부모를 위해 `shared::persistence`를, 요청자와 기사 계약을 판정하기 위해 `organization`을, 요청자 계정을 받기 위해 `auth`를, 탈퇴 차단 판정을 구현하고 탈퇴 이벤트를 구독하기 위해 `profile`을 허용합니다. schedule의 organization 의존 때문에 organization은 schedule 타입에 의존할 수 없습니다. 역할 변경의 작업중 확인과 역할 변경·비활성화의 대기함 반환, 작업 유형 삭제의 영향 건수 확인은 organization이 선언하고 schedule이 구현하는 [요구 인터페이스](../../.claude/skills/dino-architecture/references/communication.md#요구-인터페이스)로 처리합니다. 대기함 반환은 `TechnicianWorkRelease` 한 호출로 organization 트랜잭션에서 함께 커밋합니다(호출 HM-292·HM-293). 작업 유형 삭제는 `WorkTypeRelease`로 영향 건수를 세고, 삭제와 같은 트랜잭션에서 시작 전 작업의 유형을 비웁니다. 마찬가지로 schedule의 profile 의존 때문에 profile은 schedule을 조회하지 않고, 탈퇴 차단 판정은 profile이 선언하고 schedule이 구현하는 요구 인터페이스 `WithdrawalBlocker`로 받습니다. `profile`은 Entity 공통 부모를 위해 `shared::persistence`를 허용하고, 웹 어댑터에서 auth 루트 계약 `AccountPrincipal`을, 탈퇴 서비스에서 `AccountClosure`를 직접 호출하므로(profile → auth) auth는 profile을 조회·구독할 수 없습니다. 탈퇴 차단 판정은 profile이 선언하고 organization·schedule이 구현하는 요구 인터페이스 `WithdrawalBlocker`로, 탈퇴 뒤처리는 두 모듈의 `AccountWithdrawn` 구독으로 처리합니다. schedule은 연결됐고(HM-320) organization은 연결 전입니다(HM-319). notification도 탈퇴한 계정의 앱 푸시 기기를 지우려고 `AccountWithdrawn`을 구독하며(profile 의존), profile은 notification을 조회·구독하지 않습니다. profile의 가입 공통 검사는 모듈 의존 없이 허용 목록 밖의 모든 `/api/**`에 적용됩니다.

모듈 목록·책임 요약·허용 의존성은 이 지도, 공개 타입·필드·동작은 개별 모듈 문서가 소유합니다. 새 모듈은 지도에 진입점을 추가하고 상세 계약은 해당 문서에 기록합니다. 같은 타입 목록을 지도·하위 지침에 복제하지 않습니다. 별도 문서가 없는 shared의 공개 타입 목록은 [모듈별 책임과 공개 계약](#모듈별-책임과-공개-계약) 표가 소유합니다.
