# 실시간 갱신 컨텍스트 (`realtime`) — Generic Subdomain

- 기획 원본: [기획 원본 색인](../planning/README.md#planning)의 [현황 파악] 정책 §6(자동 갱신·연결 끊김)·기능명세 §4·§7, [현장 수행] 정책 §5·§13(즉시 반영), [알림] 기능명세 §7(웹 헤더 배지). 표기는 색인을 따른다
- 다른 컨텍스트와의 관계: [바운디드 컨텍스트 지도](bounded-contexts.md#realtime)
- 방식을 고른 이유: [ADR-006](../adr/006-web-realtime-sse.md)

이 문서는 `realtime`의 구현 결정과 Notion 기획과의 차이를 소유한다. 어느 화면이 무엇을 언제 다시 조회할지는 다시 적지 않고 Notion 절 번호로만 참조한다.

## 개요

| 항목 | 내용 |
| --- | --- |
| 책임 | 사무실 웹 화면(진행 보드·타임테이블·헤더 알림 배지)에 다시 조회하라는 신호를 보내는 SSE 연결을 열고 유지한다. 바뀐 내용은 보내지 않고 화면이 REST로 다시 조회한다 |
| 상태 | 구현(HM-281) — 연결 열기·유지·종료, 작업 저장·알림 변경 신호 전달(Redis Pub/Sub) |
| 소유 개념 | 연결 — 인스턴스 메모리에만 있고 DB·Redis에 남기지 않는다. 신호(`RealtimeSignal`) — 인스턴스 사이로 보내는 값이며 저장하지 않는다. 도메인 애그리게잇은 없다 |
| 관계 | `organization` → 참조(ID) (연결 요청자가 발주사의 활성 직원인지 공개 계약 `OrganizationMemberLookup`으로 직접 확인. Conformist: 직원 여부만 보므로 번역할 모델이 없어 ACL을 두지 않는다) · `auth` → 요청 계정(`AccountPrincipal`) · `schedule`·`notification` ← 이벤트 구독(`WorkChanged`·`NotificationCreated`·`NotificationRead`, 커밋 뒤 신호, Conformist: 식별자·시각만 옮기므로 번역할 모델이 없다) |

<a id="realtime-implementation"></a>
## 구현 결정

- **연결 열기**: 발주사 단위 스트림 하나(`GET /api/v1/organizations/{organizationId}/events`)를 화면들이 함께 쓴다. 발주사의 활성 직원(총관리자 포함)만 연다. 기사 앱은 자동 갱신 요구가 없어 받지 않는다. 화면 계약은 OpenAPI 설명이 원본이고, 코드에서는 이벤트 이름을 domain `RealtimeMessage`가, 이벤트 값(JSON)을 `SseRealtimeChannel`이 정한다.
- **트랜잭션 없음**: 권한 확인은 organization 조회의 읽기 트랜잭션으로 끝내고 연결 중에는 DB 연결을 잡지 않는다. `spring.jpa.open-in-view: false`가 전제이며, 켜면 연결마다 DB 커넥션을 수명 동안 붙잡는다. 권한은 연결을 열 때만 보므로, 연결을 연 뒤 소속이 바뀌거나 토큰이 폐기돼도 열린 연결은 수명이 끝날 때까지 신호를 받는다. 신호는 식별자뿐이고 다시 조회하는 REST가 권한을 다시 확인한다.
- **상한**: 인스턴스 상한(기본 2,000)은 세마포어 허가로 지키고, 넘으면 503(REALTIME-002)과 `Retry-After`로 거부한다. 계정 상한(기본 5)은 등록할 때 그 계정의 가장 오래된 연결에 `closed`(replaced)를 보내고 닫아 지킨다. 두 상한 모두 인스턴스마다 따로다. 허가는 목록에서 뺄 때 한 번만 돌려주고, 유지 신호 간격마다 허가 수와 목록 크기를 맞춰 본다(`realtime.connections.drift`).
- **전송**: 연결마다 보낼 것을 줄 세워(최대 100개, 넘으면 닫음) 전송 스레드(기본 8개)에서 하나씩 쓴다. 쓰기에 실패하면 닫는다. 쓰기 하나가 5초보다 오래 막히면 목록에서 빼고 허가를 돌려준 뒤 닫기를 줄 세운다. 막힌 쓰기가 SseEmitter 잠금을 쥐고 있어 다른 스레드가 닫으면 그 스레드도 막히므로, 막힌 쓰기가 끝나면(성공하든 컨테이너의 쓰기 한도에서 실패하든) 전송 작업이 이어서 닫는다. 그동안 전송 스레드 하나가 붙잡히며, 전송 스레드가 모두 막히면 다른 연결의 유지 신호도 늦어진다.
- **유지 신호와 수명**: 15초마다 주석 줄(`:ping`)을 보내 앞단(CloudFront 오리진 응답 대기 30초)이 조용한 연결을 끊지 않게 한다. 30분이 지나면 `reconnect`를 보내고 닫는다. 수명은 연결마다 최대 10% 앞당겨, 배포 뒤 한꺼번에 연결한 화면들이 다시 한꺼번에 연결하지 않게 한다.
- **종료**: 연결 목록은 기본 phase의 `SmartLifecycle`이라 웹 서버의 정상 종료보다 먼저 멈춘다. 새 연결을 503으로 거부하고 모든 연결에 `reconnect`를 보낸 뒤 닫아, 정상 종료(30초)가 열린 연결을 기다리지 않고 화면이 새 인스턴스로 다시 연결하게 한다. 실행기는 시작할 때마다 새로 만들어 멈춘 뒤(테스트 컨텍스트 일시정지 등) 다시 시작할 수 있다.
- **비동기 재디스패치**: 연결이 끝나면 컨테이너가 같은 요청을 ASYNC로 다시 디스패치한다. Bearer 인증은 최초 요청에서만 하므로 이 경로의 ASYNC 디스패치만 인가에서 뺀다(`RealtimeSecurityCustomizer`). 화면이 연결을 끊어 생기는 `AsyncRequestNotUsableException`은 전역 처리기가 응답 없이 넘긴다.
- **오류 응답**: 화면은 `Accept: text/event-stream`으로 요청하므로 전역 처리기는 본문이 있는 오류 응답을 Accept와 관계없이 JSON으로 쓴다. 응답 형식을 맞출 수 없는 요청(이벤트 스트림을 받지 않겠다는 요청 등)은 본문 없이 406이다. `Retry-After`는 다른 출처의 화면도 읽도록 CORS 노출 헤더에 넣는다.
- **지표**: 정상으로 끝난 연결 요청은 수명 동안 이어져 HTTP 요청 시간 지표(`http.server.requests`)의 분위수를 흐리므로 그 지표에서 뺀다(`RealtimeMetricsConfig`). 거부·오류로 끝난 요청은 남긴다. 진행 중 요청 지표(`http.server.requests.active`)에는 열린 연결이 그대로 잡힌다. 연결 상태는 `realtime.connections*`, 구독 여부는 `realtime.subscription.listening`으로 본다. 구독 여부는 처음 구독이 열리기 전과 멈춘 뒤에만 0이고 구독한 뒤 연결이 끊겨도 1이라, 경보는 발행 성공 수와 받은 신호 수도 함께 본다([ADR-006](../adr/006-web-realtime-sse.md) 감시).
- **연결 포트 위치**: 연결(`RealtimeChannel`)은 입력 포트 패키지에 두고 웹 어댑터가 구현해 연결 열기 요청에 넘긴다. 연결 목록(출력 어댑터)도 이 타입으로 보낸다. 입력 어댑터는 출력 포트를 참조할 수 없고, 연결은 요청이 가져오는 입력이기 때문이다. 출력 어댑터가 입력 포트 패키지의 다른 타입(유즈케이스)을 부르지 않는 것은 검사로 막혀 있지 않으므로 리뷰로 지킨다.
- **화면 종류**: `X-Orbit-Client` → `Sec-CH-UA-Mobile` → User-Agent 순서로 판별하며 지표 태그(`client`)로만 쓴다.
- **신호 발행**: 일반 `@EventListener`가 발행 트랜잭션 안에서 이벤트를 받아 커밋 뒤 동작을 걸고, 커밋되면 신호 전용 실행기(한 스레드, 줄 1,000개)가 Redis 채널 `orbit:realtime`으로 보낸다. 롤백되면 보내지 않는다. `@TransactionalEventListener(AFTER_COMMIT)`을 쓰지 않는 것은 Modulith가 그런 리스너를 모두 감싸 DB로 발행 상태를 갱신하기 때문이다(ADR-004). 리스너와 커밋 뒤 동작은 발행 쪽 트랜잭션·스레드에서 돌므로 예외를 던지지 않는다. 신호는 이벤트 발행 기록 대상이 아니며 보내지 못한 신호는 다시 보내지 않는다. 줄이 차거나 줄에서 30초보다 오래 기다린 신호는 버린다(`realtime.signals.dropped`의 사유 `queue_full`·`stale`, 그 밖에 신호를 만들지 못한 `invalid`·실행기가 멈춘 `stopped`). Redis 명령이 막혀(기본 대기 60초) 쌓인 신호가 Redis가 돌아온 뒤 한꺼번에 나가지 않게 하기 위해서다. 전용 실행기를 두는 것은 Redis가 멈췄을 때 요청 스레드와 다른 모듈 리스너의 실행기를 붙잡지 않기 위해서다. 실행기는 웹 서버 정상 종료가 끝난 뒤, Redis 연결보다 먼저 멈춘다.
- **신호 전달**: 모든 인스턴스가 채널을 구독해 받은 신호를 Redis 클라이언트의 수신 스레드에서 바로 연결 목록에 줄 세운다. 작업 신호는 그 발주사로 연 연결에, 알림 신호는 알림센터가 계정 단위이므로 그 계정의 모든 연결(발주사와 관계없이)에 보낸다. 연결 수가 상한으로 묶여 있고 신호가 드물어 색인 없이 목록을 훑는다. 채널 형식(JSON의 `type`·대상·시각)은 발행 어댑터와 구독 어댑터가 각자 정의하고(입력 어댑터가 출력 어댑터를 참조할 수 없음) 통합 테스트가 맞물리는지 확인한다. 읽을 수 없는 신호는 버린다(`realtime.signals.received`).
- **Redis 없이 기동**: 구독 컨테이너는 처음 구독에 실패하면 다시 시도하지 않으므로, `RealtimeSignalSubscription`이 별도 스레드에서 연결될 때까지 5초마다 다시 시작한다. 시작은 첫 시도가 끝날 때까지만(최대 3초) 기다려 Redis가 있으면 기동을 마치기 전에 구독이 열린다. 그래서 Redis에 연결할 수 없어도 기동은 막지 않는다(연결 요청의 Access Token 확인은 Redis를 쓰므로 요청은 실패한다). 구독한 뒤 끊기면 Redis 클라이언트가 다시 연결하며 다시 구독한다. 듣기만 하는 연결이라 통로만 사라진 경우는 Redis 클라이언트(Lettuce 7)의 기본 TCP keepalive(13초 쉬면 13초 간격으로 3번 확인)로 1분 안에 알아챈다. 따로 설정하지 않은 기본값이므로 Redis 클라이언트 옵션을 바꿀 때 유지한다.
- **유즈케이스 입력**: 신호 발행·전달 유즈케이스는 Command 대신 domain 값 `RealtimeSignal`을 받는다. 식별자·시각만 담은 불변 값이라 감쌀 이유가 없어서다.
- **놓친 신호**: Redis Pub/Sub은 저장하지 않아 구독이 끊긴 동안의 신호, 다른 인스턴스로 다시 연결하는 사이의 신호는 받지 못한다. 화면은 `connected`를 받을 때마다(처음·다시 연결) 보고 있는 목록을 다시 조회하고, 주기 조회로 나머지를 맞춘다.
- **설정**: `app.realtime.connection.*`(`RealtimeConnectionProperties`)와 `app.realtime.stream.*`(`RealtimeStreamProperties`). 응답의 안전 한도(기본 31분)는 연결 수명보다 길게 둔다.

| Notion 결정 필요 | R-10 | 실시간 갱신은 진행 보드만 명시돼 있다([현황 파악] §6). 타임테이블([스케줄·배정])과 헤더 알림 배지([알림] 기능명세 §7)가 새로고침 없이 바뀌어야 하는지는 명시되지 않았다. 서버는 조직의 모든 작업 저장과 계정의 알림 변경을 신호로 보내고, 어느 화면이 반응할지는 화면이 정한다 | 미등록 |
| Notion 결정 필요 | R-11 | 계정당 동시 연결 5개(인스턴스마다)를 넘으면 그 계정의 가장 오래된 연결을 `closed`(replaced)로 닫고, 그 화면은 다시 연결하지 않는다. 교체는 연결 순서로 정하므로 탭이 많은 계정에서 다른 탭이 다시 연결하면 멀쩡한 탭의 갱신이 멈출 수 있다. 그 화면에 무엇을 보일지(새로고침 안내 등)와 상한 값이 Notion에 없다 | 미등록 |
| Notion도 미정 | R-30 | 연결이 끊겼을 때의 표시가 문서마다 다르다(배너 / 자동 재연결 3회 / 전체 오류 화면). 서버는 `reconnect`·`closed`·503과 `Retry-After`까지만 정하고 표시는 화면이 정한다 | 미등록 |
