# 문서와 ADR 관리

| 원본 | 내용 |
| --- | --- |
| Notion 기획 문서 ([기획 원본 색인](../../planning/README.md#planning)) | 제품 결정 — 누가·무엇을·언제, 사용자가 체감하는 제한·표시 |
| `AGENTS.md` / `.codex/agents/` | 공통 제약·호출 조건 / 역할별 실행 절차 |
| `docs/conventions/` | 사람·구현자·검토자·CI가 공유하는 개발 계약·양식·승인 정책 |
| README / 도메인 문서 / 소스·테스트 지침 | 실행 안내 / 책임·공개 타입·흐름·미구현 범위 / 경로별 작업 경계 |
| ADR / 트러블슈팅 | 현재 선택의 이유·제약·영향 / 반복 조사에서 얻은 재사용 가능한 발견 |

- 같은 규칙의 원본은 한 곳에 둡니다. 역할로 이전한 절차의 기존 본문·읽기 지시는 삭제하고 참조를 갱신합니다. 긴 자료는 필요한 절에 직접 연결하며 인덱스를 필수 경유지로 만들지 않습니다. 승인·인증·데이터·검증 조건을 축약 과정에서 누락하지 않습니다.
- 제품 결정은 레포에 다시 적지 않습니다. BC 문서는 절 참조·구현 결정·차이만 두고 기준 버전·확인일은 색인이 소유하며, 동기화 절차는 [기획 원본 색인](../../planning/README.md#sync)이 소유합니다.
- 구조·정책·계약 변경은 소유 문서와 관련 ADR을 함께 갱신합니다. 기능 추가만으로 모든 문서를 수정하지 않으며 하위 지침에 타입 목록·구현 현황을 복제하지 않습니다. shared 공개 타입은 [도메인 지도](../../domain/README.md)가 소유합니다.
- [ADR-001](../../adr/001-backend-architecture.md)은 백엔드 아키텍처, [ADR-002](../../adr/002-agentic-coding-rules.md)는 에이전틱 코딩, [ADR-003](../../adr/003-planning-source-of-truth.md)은 기획 원본과 레포 문서의 역할 분리의 현재 결정을 유지합니다. 동일 주제 보완은 기존 ADR을 고치고 과거는 Git 이력에 둡니다. 취소선·대체 원문·실행 일지를 현재판에 누적하지 않습니다.
- 독립 결정만 새 ADR로 작성합니다. 상태(Accepted/Proposed)·기준일·배경·결정·영향·검증·관련 ADR과 [색인](../../adr/README.md)을 맞춥니다. 반복 발견은 [트러블슈팅 규칙](../../troubleshooting/README.md#기록-규칙)에 기록합니다.
