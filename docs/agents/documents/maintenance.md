# 문서와 ADR 관리

문서를 수정할 때 읽습니다. 원본 내용을 담당 파일에 유지하고, 다른 문서는 필요한 파일·명시적 앵커로 연결합니다. 작업 단계·책임이 다르면 실제 디렉터리와 목적별 파일로 분리하며 목차를 필수 읽기 경유지로 만들지 않습니다.

| 소유 문서 | 유지할 내용 |
| --- | --- |
| 루트 README / 온보딩 | 소개·빠른 시작 / 개발자의 템플릿 적용·실행 안내 |
| 컨벤션 / `docs/agents/` | 상세 개발 규칙 / 에이전트 탐색·협업·실행 정책 |
| 도메인 지도 / 모듈 문서 | 목록·책임 요약·허용 의존성·진입점 / 공개 타입·필드·흐름·미구현 범위 |
| 소스·테스트 하위 지침 | 작업 경계·검사 안내. 타입 목록·구현 현황을 복제하지 않음 |
| ADR / 트러블슈팅 | 선택 이유·제약·영향 / 반복 조사에서 얻은 재사용 가능한 발견 |

- 별도 모듈 문서가 없는 shared의 공개 타입은 도메인 지도가 소유합니다. 일상 실행·환경 안내는 빠른 시작·프로필 규칙에 직접 연결합니다.
- 기능 추가만으로 모든 컨벤션·ADR을 바꾸지 않습니다. 계약·실행법은 소유 문서에, 규칙·설계 결정은 해당 컨벤션·ADR에 반영하고 영향받는 링크·핵심 제약을 맞춥니다. 인증·데이터·승인 제약을 축약 과정에서 삭제하지 않습니다.
- 반복 발견은 [트러블슈팅](../../troubleshooting/README.md#기록-규칙)에 기록하며 일회성 실행 이력을 상시 문서에 누적하지 않습니다.
- [ADR-001](../../adr/001-backend-architecture.md)은 아키텍처, [ADR-002](../../adr/002-agentic-coding-rules.md)는 에이전틱 코딩 규칙의 현재 결정을 유지합니다. 같은 주제의 보완은 기존 ADR과 관련 문서에 반영하며 작은 보완마다 새 ADR을 만들지 않습니다.
- 기존 주제로 설명할 수 없는 독립 결정만 새 ADR로 추가합니다. 상태·기준일·배경·결정·영향·검증·관련 ADR을 명시합니다.
- 적용 중이면 Accepted, 미결정이면 Proposed입니다. 결정 변경은 현재 내용·이유·제약을 갱신하고 과거는 Git 이력에 보존합니다. 대체 원문·취소선·후속 링크를 현재판에 누적하지 않습니다.
- [ADR 색인](../../adr/README.md)은 현재 주제·범위·원본 링크만 유지합니다. 구조·정책 변경 시 관련 문서·색인의 경로·앵커·일관성을 검사합니다.
