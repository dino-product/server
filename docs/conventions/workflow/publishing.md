# AI 게시물 작성

이슈·PR의 초안·작성 요청에 적용합니다.

1. 요청이 초안인지 실제 게시까지인지 [루트 작업 원칙](../../../AGENTS.md#작업-원칙)으로 구분합니다. 확인 대상만 [승인 안내](approvals/README.md#approvals)를 적용하며 동일 요약·승인 범위는 재확인하지 않습니다. 양식 추가 요청은 실제 게시 권한이 아닙니다.
2. 요청 범위의 코드·문서·이슈·현재 Git 상태를 확인합니다. PR은 기준 브랜치·최종 제출 diff를 확인하며 함께 있는 작업 트리 변경을 PR 포함 변경으로 오인하지 않습니다.
3. 목적에 맞는 유형·양식을 선택합니다. 이슈는 [Form 작성](issues/forms.md#forms), PR은 [PR 작성](pull-requests/writing.md#writing)을 적용합니다. PR 제목 유형·라벨·최종 diff 목적을 일치시킵니다.
4. 사실·가설·미확인을 구분하고 실제 검증만 인용합니다. 계획·이전 결과를 이번 통과로 쓰지 않고 이슈 번호·링크·담당자·일정·체크 항목을 추정하지 않습니다.
5. 요구사항·대화 전체를 복사하지 말고 결과부터 설명합니다. 범위가 바뀌면 제목·본문을 최종 변경 기준으로 다시 쓰며 작업 일지·임시 계획을 저장소 문서에 누적하지 않습니다.
6. 초안은 사용자 언어로 제목·본문·라벨을 함께 제시합니다. 게시 권한이 있으면 저장소·브랜치·연결 이슈를 확인해 게시하고 URL을 보고합니다. 구현·필수 검증 미완료 PR은 Draft로 게시하고 남은 내용을 본문에 적습니다.

여러 줄 본문은 임시 파일에 실제 줄바꿈으로 작성해 `gh issue create --body-file` 또는 `gh pr create --body-file`로 전달합니다. 게시물의 파일 링크는 대상 저장소·브랜치 또는 커밋의 실제 URL을 사용하며 로컬 절대 경로를 넣지 않습니다. [이슈 CLI](https://cli.github.com/manual/gh_issue_create)·[PR CLI](https://cli.github.com/manual/gh_pr_create)
