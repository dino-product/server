# AI 리뷰

리뷰 요청만으로 코드 수정·댓글 게시를 하지 않습니다. [자동 검사와 리뷰의 역할](../../testing/evidence.md#evidence)에 따라 유효한 결과를 재사용하고 미검증 요구사항·영향·검사 자체의 적절성을 검토합니다.

1. **범위:** 목적·완료 조건·실제 base/head SHA를 확인합니다. 같은 SHA의 통계·커밋 순서가 있으면 재사용합니다. 없거나 기준이 바뀌면 `git diff --stat <base-sha>...<head-sha>`, `git diff --numstat <base-sha>...<head-sha>`, `git log --reverse --format='%h %s' <base-sha>..<head-sha>`로 확인합니다. 선행 PR과 현재 차이를 구분하고 같은 SHA로 리뷰합니다.
2. **읽기:** 커밋 순서와 관련 구현·호출부·테스트를 따라 필요한 범위씩 읽습니다. 출력 한도를 지키되 함수·계약 중간을 끊지 않고 필요한 주변 코드·선행 연결을 확인합니다. 내부 묶음으로 사람용 PR 분리를 대신하지 않습니다.
3. **검토:** 요구사항·실패 경로·테스트 누락·커밋별 한 변경 이유·중간 상태 완결성을 확인합니다. 최종 상태 검사와 커밋별 근거를 구분하고 조립 변경 등 미해결 우려가 있으면 해당 커밋의 집중 검사를 선택합니다. 발견은 위치·발생 조건·영향·근거를 갖추고 가설·확정 결함을 구분합니다.
4. **연결:** 모든 묶음 후 호출부·공개 계약·구현·설정·테스트의 일치를 확인합니다. 변경에 해당하는 [모듈 경계](../../architecture/modules.md#modules)·[소비자 변환](../../architecture/external-models.md#external-models)·[내부 의존성](../../architecture/layers.md#layers)을 적용해 변경 전파를 확인합니다. 묶음 간 미확인 사항을 해소하고 동일 원인 지적을 합칩니다.
5. **보고:** 중요한 결함부터 검토한 커밋·묶음 수·검증 결과·미확인 범위를 알립니다. 일부 검토를 전체 완료로, 미실행 검사를 통과로 보고하지 않습니다. head가 바뀌면 새 diff·영향받는 연결을 다시 확인합니다.

새 파일·삭제·이름 변경도 검토합니다. 생성물·잠금 파일·바이너리는 별도 표시하고 생성 원본·의존성 변경·파일 영향에 맞게 확인합니다. `numstat`에 줄 수가 없는 바이너리를 0줄로 보거나 큰 파일을 조용히 제외하지 않습니다.

대상 파일/hunk·묶음 목록·남은 연결·중간 메모는 대화·임시 파일에만 둡니다. 세팅 산출물로 저장소 문서에 누적하지 않고 PR에는 필요한 리뷰 순서·미분리 이유·중요 의존 관계만 남깁니다.
