# 대화 승인 후에도 Codex 명령이 거절됨

## 증상과 발생 조건

실행 결과에 다음 오류가 나오며 명령이 시작되지 않습니다.

```text
approval required by policy, but AskForApproval is set to Never
```

실제 세션의 승인 모드는 `never`이고 명령에는 승인이 필요한 실행 정책이 적용되는 경우입니다. 프로젝트의 [실행 규칙](../../.codex/rules/codex-commands.rules)은 `git push` 등에 `prompt`를 지정합니다. 오류만으로 어느 사용자·프로젝트 규칙이 일치했는지까지 단정하지 않습니다.

## 원인과 대응

대화에서 받은 행위 승인과 실행 도구의 승인 가능 여부는 별개입니다. 같은 요청을 다시 승인해도 현재 세션이 도구 승인을 받을 수 있게 바뀌지는 않습니다.

1. 세션에 실제 적용된 승인 모드와 명령의 거절 사유를 확인합니다. 다른 세션이나 설정 파일의 값만으로 현재 모드를 추정하지 않습니다.
2. 대상·변경 요약과 준비 결과를 남기고 독립 작업을 계속합니다. 사용자는 승인 가능한 실행 환경에서 진행하거나 해당 명령을 수동 실행할 수 있습니다.
3. 수동 실행 이후에는 원격 상태 등 실제 결과를 조회한 뒤 후속 작업을 진행합니다. 상태 확인 전 성공했다고 보고하지 않습니다.

## 검증과 한계

`codex exec --help`로 해당 설치 버전의 옵션을 확인하고, 실행 규칙 평가는 [실행 정책 안내](../agents/execution-policy.md)의 명령으로 수행합니다. 규칙 평가만으로 세션의 실제 로딩이나 승인 UI가 검증되지는 않습니다. 확인을 위해 푸시 등 외부 변경을 시험 실행하지 않습니다.

정책 원본은 [승인 절차](../conventions/workflow/approvals/README.md#approvals)입니다. 승인 모드·규칙 변경, 명령 별칭·다른 도구를 통한 우회는 해결책으로 사용하지 않습니다.
